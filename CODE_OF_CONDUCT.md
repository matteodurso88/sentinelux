# Sentinelux Code of Conduct / Codice di condotta Sentinelux

[Italiano](#italiano) · [English](#english)

## Italiano

### Impegno

La comunità Sentinelux vuole offrire uno spazio tecnico rispettoso, collaborativo e accessibile. Chi partecipa a issue, pull request, review, discussioni o altri canali del progetto deve trattare le altre persone con professionalità, indipendentemente da esperienza, identità, provenienza, capacità, età, convinzioni o ruolo nel progetto.

### Comportamenti attesi

- comunicare in modo chiaro, rispettoso e orientato ai fatti;
- criticare il codice o l'idea, non la persona;
- accettare feedback tecnici e correggere gli errori;
- dichiarare limiti, incertezze e possibili rischi;
- proteggere dati personali e informazioni riservate;
- lasciare spazio a chi ha meno esperienza;
- rispettare le decisioni di moderazione e manutenzione.

### Comportamenti non accettati

- insulti, minacce, molestie o discriminazioni;
- linguaggio sessualizzato o attenzioni indesiderate;
- attacchi personali, provocazioni reiterate o trolling;
- pubblicazione di dati personali senza consenso;
- pressioni per aggirare review, protezioni del branch o verifiche di sicurezza;
- uso del progetto per danneggiare sistemi, persone o dati;
- divulgazione pubblica irresponsabile di vulnerabilità.

### Applicazione

I maintainer possono modificare o rimuovere contenuti, chiudere issue o pull request, limitare la partecipazione e adottare altri provvedimenti proporzionati. Le decisioni devono considerare gravità, ripetizione, impatto e volontà di correggere il comportamento.

Per segnalare un problema di condotta, evita di pubblicare dettagli sensibili. Usa un canale privato indicato nel profilo GitHub del maintainer. Se non è disponibile, apri una issue neutra intitolata `Conduct contact request` senza descrivere pubblicamente l'accaduto; il maintainer stabilirà un canale riservato.

Questo codice si applica negli spazi del progetto e quando una persona rappresenta pubblicamente Sentinelux.

## English

### Commitment

The Sentinelux community aims to provide a respectful, collaborative, and accessible technical space. Anyone participating in issues, pull requests, reviews, discussions, or other project channels must treat others professionally, regardless of experience, identity, background, ability, age, beliefs, or project role.

### Expected behavior

- communicate clearly, respectfully, and based on evidence;
- criticize code or ideas rather than people;
- accept technical feedback and correct mistakes;
- disclose limitations, uncertainty, and potential risks;
- protect personal and confidential information;
- make room for less experienced contributors;
- respect moderation and maintenance decisions.

### Unacceptable behavior

- insults, threats, harassment, or discrimination;
- sexualized language or unwanted attention;
- personal attacks, repeated provocation, or trolling;
- publishing personal data without consent;
- pressuring others to bypass review, branch protection, or safety checks;
- using the project to harm systems, people, or data;
- irresponsible public disclosure of vulnerabilities.

### Enforcement

Maintainers may edit or remove content, close issues or pull requests, limit participation, and take other proportionate action. Decisions should consider severity, repetition, impact, and willingness to correct the behavior.

To report a conduct concern, do not publish sensitive details. Use a private contact method listed on the maintainer's GitHub profile. When none is available, open a neutral issue titled `Conduct contact request` without describing the incident publicly; the maintainer will establish a private channel.

This code applies in project spaces and when someone publicly represents Sentinelux.
